## What's new here

Most guides run Z-Image Turbo as a **GGUF** file, because that's the usual way to squeeze a 6B model onto a small GPU.
On consumer RTX cards that turns out to be the slow path. This repo uses a different combination:

| | Common setup | freeimage local |
|---|---|---|
| Weights | GGUF Q8_0 / Q5_K_M | **int8_convrot** safetensors |
| Attention | flash attention | **native CUDA SageAttention** |
| Engine | ComfyUI | **stable-diffusion.cpp** (`sd-server`) |
| 1024², 8 steps, RTX 3060 6 GB | 24–27 s | **14.4–16.3 s** |

<p align="center"><img src="assets/speed.svg" alt="Bar chart: GGUF Q5 28.0 s, GGUF Q8 25.5 s, int8_convrot 15.8 s, int8_convrot with SageAttention 15.4 s" width="720"></p>

**About 40% faster, at the same quality.** On 10 test prompts scored by a vision model, GGUF Q8 and int8 + SageAttention both scored 73/100
(prompt adherence 2.73 vs 2.72, image quality 2.07 vs 2.08, artifacts 29% vs 28%). Full numbers: [docs/benchmarks.md](docs/benchmarks.md).

Why it works:

- **int8 instead of GGUF.** stable-diffusion.cpp runs int8 weights with integer matrix kernels. GGUF K-quants are unpacked on the fly,
  and on this card that costs more than it saves. The smaller Q5 file was even slower than Q8.
- **SageAttention** (`--sage-attn`) adds a small extra gain with no visible change. It's CUDA-only.
- **Weights live in RAM and stream into VRAM.** The int8 model is 6.2 GB and the text encoder 4.3 GB. With `--offload-to-cpu`, the
  engine prefetches the next block while the current one runs, so 6 GB of VRAM is enough. Don't disable prefetch: that costs ~20%.
- **Kept warm.** `fi serve` loads the model once. In production on freeimage.dev, a 1024² image takes **12.6 s at 6 steps** (average
  of 54 images) and **15.3 s at 8 steps**, text encoding and VAE decode included.

## Hardware

| Machine | Status | Notes |
|---|---|---|
| NVIDIA RTX 30-series, Linux | ✅ **Tested** | RTX 3060 Laptop 6 GB, 16 GB RAM, CUDA 12.4. Runs freeimage.dev 24/7. |
| NVIDIA RTX 40-series, Linux | Should work | Same code path, architecture detected automatically. |
| NVIDIA RTX 50-series (5060, 5070…), Linux | Should work | Needs CUDA 12.8+ for `sm_120`. The installer checks this. |
| NVIDIA GB10 (DGX Spark), Linux | Tuned | `sm_121`, ~120 GB unified memory. `nvidia-smi` reports VRAM as N/A — installer uses system RAM, enables SageAttention + `--eager-load`, never `--offload-to-cpu`. Needs CUDA 12.8+. |
| NVIDIA Turing (RTX 20xx, Quadro RTX), Linux | Tuned | `sm_75` builds fine on CUDA 12/13. SageAttention needs Ampere+ (`sm_80`), so the engine uses flash attention + `--eager-load` on 16 GB+ VRAM (no CPU offload). |
| Windows + NVIDIA | Should work in WSL2 | Use the Linux steps inside WSL2 with the NVIDIA CUDA-on-WSL driver. |
| Apple Silicon Mac | ✅ Tuned | Metal build. No SageAttention. On ≤18 GB unified memory, installs a Q4 text encoder and pins DiT on GPU (TE on CPU) so sampling does not thrash. Never use `--offload-to-cpu` on Mac. |

Only the NVIDIA row has full quality benches. **If you run it on something else, please share `./fi bench` output in an issue**,
and I'll add your numbers to this table.

You need about 9–11 GB of free disk (Metal ≤18 GB downloads the smaller Q4 text encoder), 16 GB of RAM, and for NVIDIA cards with less than 12 GB of VRAM the weights are offloaded automatically. Cards with 16 GB+ VRAM keep the full model resident (`--eager-load`) for faster warm sampling.

## Install

**macOS (Apple Silicon)**
```bash
xcode-select --install          # if you don't have the command line tools
brew install cmake ninja
./install.sh
```

**Ubuntu / Debian with an NVIDIA GPU**
```bash
sudo apt install git cmake ninja-build build-essential curl
# CUDA toolkit: https://developer.nvidia.com/cuda-downloads (12.8+ for RTX 50-series)
./install.sh
```

The installer:
1. detects your GPU (Metal, or CUDA with the right `sm_XX` architecture),
2. builds a pinned, tested version of [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp),
3. downloads the three model files with resume support and checks their SHA-256.
   If Hugging Face rate-limits you, set `HF_TOKEN` (from [settings/tokens](https://huggingface.co/settings/tokens)): `HF_TOKEN=hf_xxx ./install.sh --models`.

Everything lives in `.fi/` inside this folder. Delete it to uninstall.

## Use

```bash
./fi "a lighthouse on a cliff, flat illustration"            # 1024×1024, 8 steps
./fi "city street at night in the rain" --size 1344x768      # 16:9
./fi "portrait of an old fisherman" --steps 6 --seed 42      # faster, reproducible
./fi serve                                                   # web UI, keeps the model loaded
./fi bench                                                   # seconds per image on your machine
./fi doctor                                                  # what was detected, which flags are used
```

`./fi "…"` loads the model for every image, which is fine for one-offs. For more than a couple of images, use `./fi serve`:
the model stays in memory and each image takes only the sampling time.

Tips:
- **Steps:** 8 is the sweet spot. 6 is ~20% faster with a slight softening of skin and fur. 4 loses visible detail.
- **Prompts:** Z-Image Turbo likes plain, descriptive English: subject, setting, light, style. No negative prompt is needed (CFG is 1.0).
- **Sizes:** any multiple of 64. 1024×1024, 896×1152 (3:4), 768×1344 (9:16) and 1344×768 (16:9) all work well. On 24 GB+ VRAM or unified memory, the UI also offers **2K** (2048×2048).

## What didn't help

Tested on the same card so you don't have to:

- `easycache`, `dbcache`, `cache-dit`: no effect at 8 steps.
- Text encoder on CPU (`--backend te=cpu`): encoding went from 0.85 s to 3.4 s, sampling unchanged.
- `--disable-prefetch`: ~20% slower.
- `--flash-attn off`: 2× slower.
- GGUF Q5 instead of Q8: smaller, but slower.
- ComfyUI with the same GGUF files: 8–30% slower than stable-diffusion.cpp.

On laptops, heat matters more than any flag. The 3060 starts throttling around 87–89 °C and runs 10–25% faster when cool.
